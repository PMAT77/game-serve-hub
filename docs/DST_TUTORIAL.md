# 饥荒联机版（DST）一键开服教程

本教程面向使用 Game Server Hub 面板开服的服主，覆盖从准备服务器到朋友进服的完整流程。安装、升级、回滚与运维排错见 [安装与运维指南](INSTALL.md)；本文专注于"把服务器开起来、管起来"。

---

## 快速答案

| 问题 | 结论 |
| --- | --- |
| 安全组要开放哪些端口？ | 面板 9527/tcp；主世界 10999/udp、8766/udp、12346/udp；**开启洞穴再加** 11000/udp、8768/udp、12348/udp |
| 面板默认对外访问地址？ | http://<服务器公网 IP>:9527 |
| 需要配置 IP 转发吗？ | **不需要**。Docker 模式由 Docker 自动完成端口映射，Native 模式进程直接监听宿主机端口 |
| 主世界/洞穴端口要手动开放吗？ | **要**。面板和安装器默认不碰云安全组，主世界与洞穴的全部 UDP 端口都需手动放行 |

---

## 1. 认识面板

Game Server Hub 是一个开源的游戏服务器运维面板，当前完整适配《饥荒联机版》（DST），提供：

- 实例创建、SteamCMD 安装/更新、启动、停止和重启
- 地上/洞穴双分片、房间、世界生成和 Mod 管理
- 主机与实例 CPU、内存、磁盘、网络监控
- SSE 实时日志、游戏控制台命令
- 存档备份与恢复、计划任务
- Docker Compose 与 Native systemd 双运行时

**两种部署模式怎么选：**

| 模式 | 适合谁 | 运行方式 |
| --- | --- | --- |
| Docker | 小型社区、托管商 | 面板与游戏均为 Docker 容器 |
| Native systemd | 个人服主 | 面板为系统服务，游戏进程由 gsh 用户的 systemd 服务管理 |

两种模式的面板功能完全一致，教程内容通用；涉及差异处会单独标注。

## 2. 准备工作

### 2.1 服务器要求

| 项目 | 要求 |
| --- | --- |
| 系统 | Ubuntu 22.04 / 24.04 或 Debian 12 |
| 内存 | 最低 4 GiB；**开洞穴**推荐 6 GiB；大量 Mod 推荐 8 GiB+（见 [内存建议](MEMORY.md)） |
| 磁盘 | 根分区至少 4 GiB 空闲，游戏本体与存档另计 |
| 权限 | root 或 sudo |
| 网络 | HTTPS 出站（下载脚本、镜像与游戏） |

只支持 apt 系发行版，不支持 CentOS/RHEL/Alpine。建议选择与玩家距离近的机房（影响联机延迟）。

### 2.2 获取 Klei 集群令牌（公网联机必须）

玩家要能从游戏内"浏览游戏"列表找到你的服务器，必须配置 Klei 集群令牌（pds- 开头）：

1. 打开 <https://accounts.klei.com/>，用 Steam 账号登录；
2. 进入 **Games（游戏）→ Don't Starve Together Servers**；
3. 点击 **Add New Server（添加新服务器）**，填写一个集群名称；
4. 复制生成的集群令牌（以 pds- 开头的长字符串），后面"创建房间"时要用。

> 只玩离线/局域网可以跳过这一步，但从联机列表进人是必须配令牌的。

## 3. 下载脚本并安装

### 3.1 一键安装命令

SSH 登录服务器后，按部署模式选择一条命令执行。

**Docker 模式**（推荐托管与社区使用）：

> 中国大陆服务器请**先导入离线镜像包，再跑这条命令**。安装器要从 GHCR 拉取统一镜像，而 GHCR 的镜像层域名在国内基本不可达，直接跑几乎必然失败（`TLS handshake timeout`）。离线包步骤见 [INSTALL.md · 离线镜像包完整步骤](INSTALL.md#离线镜像包完整步骤国内推荐先读这一节)。

```bash
curl -fsSL https://raw.githubusercontent.com/PMAT77/game-serve-hub/v0.3.5/scripts/install.linux.sh \
  | sudo bash -s -- --mode docker
```

**Native systemd 模式**（推荐个人服主，不依赖 Docker）：

```bash
curl -fsSL https://raw.githubusercontent.com/PMAT77/game-serve-hub/v0.3.5/scripts/install.linux.sh \
  | sudo bash -s -- --mode native
```

**国内网络**（GitHub Raw 不稳定时，换 jsDelivr 源并启用国内档位）：

```bash
curl -fsSL https://cdn.jsdelivr.net/gh/PMAT77/game-serve-hub@v0.3.5/scripts/install.linux.sh \
  | sudo bash -s -- --mode native --network cn
```

建议**明确指定 --mode**，避免自动判断与你的预期不一致。

### 3.2 安装参数

| 参数 | 说明 |
| --- | --- |
| --mode auto\|docker\|native | 部署模式；管道安装时 auto 默认选 Docker |
| --network auto\|cn\|global | 网络档位；cn 临时切换国内软件源、提高 SteamCMD 重试，失败自动还原 |
| --open-panel-port | 安装时在本机防火墙（ufw/firewalld）放行面板 9527/tcp |
| --open-dst-ports | 安装时在本机防火墙放行 DST 游戏端口 |

> 安装器默认**不修改任何防火墙**。加了 --open-* 参数也只影响本机防火墙，云厂商安全组永远需要你手动放行（见第 4 章）。

### 3.3 安装器做了什么

- 检查系统、磁盘、端口与网络连通性；
- **Docker**：安装 Docker 与 Compose，下载 Compose 文件，生成 panel.env，拉取统一镜像（面板 + DST 运行库 + SteamCMD 三合一）并启动；
- **Native**：安装 SteamCMD 及 i386 运行库，创建 gsh 系统用户，下载校验 Native Release，注册 game-server-hub.service 并启动；
- 生成随机初始密码写入权限受限的 /opt/game-server-hub/panel.env，安装摘要给出访问地址。

安装完成后先验证健康状态：

```bash
curl -fsS http://127.0.0.1:9527/health
```

返回 JSON 中 runtime.status 为 running 即正常。安装失败时看 /var/log/game-server-hub/install.status 与 install.diagnostics.log。

## 4. 开放端口：安全组与防火墙

### 4.1 需要开放的端口清单

| 用途 | 协议 | 默认端口 | 何时需要 |
| --- | --- | --- | --- |
| 面板 Web | TCP | 9527 | 始终需要 |
| 主世界 · 游戏端口 | UDP | 10999 | 始终需要 |
| 主世界 · Steam 认证端口 | UDP | 8766 | 始终需要 |
| 主世界 · Steam 主服端口 | UDP | 12346 | 始终需要 |
| 洞穴 · 游戏端口 | UDP | 11000 | 开启洞穴时需要 |
| 洞穴 · Steam 认证端口 | UDP | 8768 | 开启洞穴时需要 |
| 洞穴 · Steam 主服端口 | UDP | 12348 | 开启洞穴时需要 |

> 如果你后来在世界设置里改过某个分片的端口，安全组要按新端口同步放行（改游戏端口后 Steam 端口不会自动跟随，需一并调整）。

### 4.2 云安全组操作

主流云厂商（阿里云、腾讯云、AWS 等）都默认拒绝入站流量，需要手动添加放行规则：

1. 登录云控制台，找到服务器的 **安全组 / 防火墙** 配置页；
2. 添加入站规则：
   - 允许 **TCP 9527**（来源 0.0.0.0/0，或仅填你自己的 IP 更安全）；
   - 允许 **UDP 10999、8766、12346**（来源 0.0.0.0/0）；
   - 开洞穴的再加 **UDP 11000、8768、12348**；
3. 保存规则后无需重启服务器。

游戏 UDP 端口必须对全网开放，玩家才能连接；面板 TCP 端口建议只对你自己的常用 IP 开放。

### 4.3 本机防火墙

- 服务器开了 ufw/firewalld 的，可用安装参数 --open-panel-port --open-dst-ports 自动放行，或手动执行 sudo ufw allow 9527/tcp、sudo ufw allow 10999/udp 等；
- 没开本机防火墙的（多数云主机默认状态）只需配置安全组即可。

## 5. 需要配置 IP 转发吗？

分场景回答，不要一概而论。

### 5.1 云服务器 / 独立 Linux 主机：不需要

- **Docker 模式**：面板容器通过端口映射发布 9527；游戏分片容器由面板动态创建，端口一比一绑定到宿主机（10999→10999），Docker 自动维护 NAT 规则，无需你开启内核 ip_forward 或写任何转发规则；
- **Native 模式**：游戏进程直接监听宿主机端口，连容器都没有。

也不需要 frp、nps 之类的内网穿透工具——那是家用电脑开服的方案，云服务器直接放行安全组即可。

### 5.2 Windows 开发环境：只保证本机进服

**Windows 不是部署目标。** 它只用于本机开发调试——本项目不提供 Windows 安装脚本，也不为"让他人联机"做兼容（原因见本节末尾）。

开发场景下只需保证一件事：**游戏客户端（与面板同一台电脑）能用「本机」档进服**。这类环境下游戏端口绑定在 **WSL 的网络命名空间**里，不由 Windows 直接监听，第 4 章的"放行安全组"说明不适用：

| 运行方式 | 本机进服 `c_connect("127.0.0.1", …)` |
| --- | --- |
| Rancher Desktop / Docker Desktop | 宿主侧自带 Windows↔WSL 端口转发（含 UDP），可用 |
| WSL 内原生 Docker（默认 NAT 模式） | 不保证可用；改用 WSL 的 IP（WSL 里执行 `hostname -I`） |

配合控制台的直连命令使用时注意：

- **本机游玩请用「本机」档。** 面板跑在容器里时看不到宿主机网卡，「局域网」档通常为空；「公网」档来自出站 IP 探测，只表示"这条线路的出口"，在家用 NAT / 容器 / 系统代理环境下往往无法直连（开着代理时甚至可能返回代理出口地址）。面板已按地址来源自动选择默认档位，显示不对可用命令框右侧按钮切换。
- **不要为了让他人联机去折腾 Windows 侧网络。** 容器运行时会额外引入一层网络边界（典型如 Rancher Desktop 只把端口绑到 `127.0.0.1`），让端口暴露成倍复杂而收益很低。需要长期开服给他人玩，请用 Linux 服务器或云主机（见 5.1），那才是本项目的目标场景。
- 需要固定覆盖进服地址时，在 `panel.env` 设置 `GSH_DST_CONNECT_HOST`（并用 `GSH_DST_AUTO_PUBLIC_IP=0` 关闭出站探测），见 [`panel.env.example`](../panel.env.example)。

> Windows 不作为部署目标的原因：桌面 Windows 会休眠、会自动更新重启，无法承担长期在线的游戏服务器；Klei 官方同样建议独立服务器搭在 Linux 上而非 Windows 上。生产部署见 [INSTALL.md](INSTALL.md)。

### 5.3 家庭宽带 / 二级路由 NAT：需要端口映射

如果你的服务器在家庭宽带或二级路由 NAT 后面（没有公网 IPv4），需要在路由器上把 4.1 的端口映射到服务器内网 IP，此时才属于"端口转发"范畴。光猫若也是路由模式，还需在光猫上再做一层映射。

映射前先确认运营商给的是**真公网 IPv4**：对比路由器 WAN 口 IP 与服务器上 `curl -s --noproxy '*' https://api.ipify.org` 的结果，一致才是真公网。若服务器出口 IP 与路由器 WAN 口对不上、且 WAN 口是 `10.` / `100.64.` / `172.16-31.` 开头，说明上游还有一层 NAT（CGNAT），端口映射不会生效，只能改用内网穿透方案。

## 6. 首次登录与修改密码

### 6.1 访问面板

浏览器打开安装摘要给出的地址，默认格式：

```text
http://<服务器公网 IP>:9527
```

例如 http://123.45.67.89:9527。如果打不开，按顺序检查：安装是否完成（/health）、安全组是否放行 9527/tcp、浏览器与服务器之间的网络。

> **云平台 NAT 转发模式**：部分云主机（尤其「云电脑」、轻量应用等产品）的公网 IP 并不与机器直连，端口需要在控制台的「**端口转发 / NAT 映射**」里显式配置。此时：
>
> - **公网端口通常是随机高位端口，与内部端口不同** —— 例如公网 `203.0.113.10:13992` 映射到内部 `8888`；
> - **只放行安全组是不够的**，必须在这里有转发规则，否则外部完全连不上（表现为超时，而不是连接被拒绝）；
> - 从服务器**内部** `curl` 自己的公网 IP 会得到 `Connection refused` —— 这是 NAT 不支持回环的正常现象，**不代表面板有问题**，别在这上面排查；
> - **DST 的游戏端口（UDP 10999 等）同样需要在这里配置**，且协议要选 UDP。玩家要用**分配到的公网端口** `c_connect`；从 Klei 列表进服可能因服务器自报的内部端口与公网端口不一致而失败。

### 6.2 读取初始密码

安装器生成随机初始密码，默认不在摘要中明文展示。在服务器上执行：

```bash
sudo awk -F= '/^ADMIN_PASSWORD=/{print substr($0, index($0, "=") + 1)}' \
  /opt/game-server-hub/panel.env
```

默认管理员用户名是 superadmin。也可以在首次安装时显式指定账号密码：

```bash
curl -fsSL https://raw.githubusercontent.com/PMAT77/game-serve-hub/v0.3.5/scripts/install.linux.sh \
  | sudo env ADMIN_USERNAME=admin ADMIN_PASSWORD='替换为强密码' \
      bash -s -- --mode native
```

### 6.3 强制修改密码

**首次登录会强制跳转到改密页**，必须设置符合强度要求的新密码后才能进入面板。这是安全设计：初始密码曾以明文存放在服务器磁盘上。

### 6.4 日常修改密码

登录后点击**右上角头像 → 个人资料**，在个人资料页选择**修改密码**，输入旧密码与新密码提交即可。建议定期更换。

### 6.5 忘记密码

- 尚未在面板内改过密：用 6.2 的命令从 panel.env 重新读取初始密码；
- 已在面板内改过密：密码以数据库中的凭据为准，panel.env 里的初始密码不再有效。不要通过反复重跑安装器来"重置"密码——同模式重跑是原地升级，不会覆盖你在面板里改过的账号。

## 7. 进入面板后的操作流程总览

登录后按下面的顺序操作，即可完成一次完整开服：

| 步骤 | 页面 | 做什么 |
| --- | --- | --- |
| 1 | 实例管理 | 确认"运行环境与安装镜像"就绪（见第 8 章） |
| 2 | 实例管理 | 创建实例（见第 9 章），自动下载安装游戏本体（见第 10 章） |
| 3 | 房间管理 → 房间设置 | 配置房间名称、联网方式、Klei 令牌、洞穴开关（见第 11 章） |
| 4 | 世界管理 → 世界设置 | 配置地上/洞穴的世界规则与生成参数（见第 12 章） |
| 5 | 模组管理（可选） | 搜索并订阅创意工坊 Mod（见第 14 章） |
| 6 | 实例管理 | 启动实例，首次启动自动生成地图（见第 15 章） |
| 7 | 实例管理 / 监控台 | 观察日志确认启动成功，玩家进服 |
| 8 | 备份与恢复 / 计划任务 | 配置日常备份与定时任务（见第 17、18 章） |

面板左侧导航与页面的对应关系：**监控台**（主机资源总览）、**实例管理**（实例列表/详情/控制台）、**房间管理**、**世界管理**、**模组管理**、**备份与恢复**、**计划任务**、**系统设置**。

## 8. 检查更新：运行环境与镜像版本

开服前和日常维护时，有两个地方负责"更新与运行环境"：

### 8.1 实例管理页：运行环境与安装镜像

打开 **实例管理** 页，顶部是"运行环境与安装镜像"折叠面板：

- 状态标签显示运行时（Docker/systemd）是否可用、SteamCMD 是否就绪、DST 运行镜像是否就绪；
- 未就绪时点击 **预拉游戏安装镜像**（Native 模式为 **检查 SteamCMD**）提前准备；
- Docker 模式还可以点 **手动拉取 DST 运行镜像**；
- 面板默认会在创建实例时自动准备镜像，这个面板用于提前检查或补拉。

### 8.2 系统设置页：面板与游戏版本

打开 **系统设置**，找到"面板与游戏版本"区块：

- 显示当前统一镜像版本（面板 + DST 运行环境 + SteamCMD 同版本）、本地与远端摘要、最新 Release 信息；
- 点击 **检查更新** 立即向镜像仓库/GitHub Release 核对；有新版本且 Docker 栈可达时，点 **应用更新** 一键拉新镜像并重建面板（会短暂重启管理端，实例存档与配置不受影响）；
- Native 模式显示手动升级命令（重跑新版安装脚本原地升级）；
- "面板镜像自动检查更新"开关可设 1–168 小时的自动检查间隔；
- "启动前检查游戏更新"开启后，每次启动实例前会向 Steam 核对服务端 Build ID，有新版本时会阻止启动，提醒你先更新游戏服务端。

游戏本体的版本更新（DST 出新补丁时）在**实例列表**的"更新服务端"操作里执行，见 10.3 节。

## 9. 创建实例

一个实例 = 一个独立的 DST 服务器（一套集群）。可以创建多个实例开多个服。

1. 进入 **实例管理**，点击 **创建实例**；
2. 填写表单：
   - **实例名称**：自定义，便于识别（也会成为默认房间名，后面可改）；
   - **游戏**：选择《饥荒联机版》（AppID 322330）；
   - **安装路径**（可选）：默认由面板统一管理，一般不用改；
3. 提交后实例以"未安装"状态出现在列表中，随后**自动开始安装**（见第 10 章）；
4. 安装过程中状态为"安装中"，点击实例可查看安装日志；完成后状态变为"已停止"，并会弹出"准备启动服务器"引导（见第 15 章）。

统计卡（全部/未安装/安装中/运行中/已停止/异常）可以直接点击筛选实例。

## 10. 下载安装饥荒游戏本体

### 10.1 自动安装

创建实例后，面板自动调用 SteamCMD 下载 DST 专用服务器完整本体：

- Docker 模式在 SteamCMD 容器内执行下载；
- Native 模式使用 /opt/game-server-hub/runtime/steamcmd 的本地 SteamCMD；
- 安装过程逐阶段可见：打开实例详情或列表中的 **安装日志**，能看到校验与下载进度。

### 10.2 国内下载慢？

- 安装服务器时使用 --network cn（将 SteamCMD 下载区域设为中国区、重试提高到 8 次）；
- 也可在 panel.env 配置 GSH_STEAMCMD_DOWNLOAD_REGION=cn、代理等参数后重启面板（见 [INSTALL.md](INSTALL.md) 第 8 章）。

### 10.3 更新游戏服务端

DST 出新版本后：

- 若系统设置里开了"启动前检查游戏更新"，启动时会被提醒先更新；
- 在实例列表的操作菜单里点 **更新服务端**，面板会用 SteamCMD 校验并补齐到最新 Build；更新前会**自动创建一份存档备份**（防止更新破坏世界）；
- 更新过程中实例不可启动，完成后正常启动即可。

## 11. 创建房间

"房间"是玩家在游戏内联机列表看到的服务器信息。进入 **房间管理**，点击实例进入 **房间设置**：

| 设置项 | 说明 |
| --- | --- |
| 联网方式 | **公网联机**：任何人可从列表搜到（需 Klei 令牌）；**局域网**：仅同内网可见；**离线**：单机模式不联网 |
| Klei 集群令牌 | 公网联机**必填**，pds- 开头（获取方法见 2.2 节）；已配置过时留空表示不修改 |
| 房间名称 | 必填，联机列表显示的名字 |
| 房间描述 | 列表中展示的简介 |
| 房间密码 | 留空为公开服；填写后只有知道密码的玩家能进 |
| 游戏模式 | 生存（默认）/ 无尽 / 荒野 / 轻松 / 暗无天日，选择后下方有模式说明 |
| 最大玩家数 | 1–64，默认 6 |
| PvP | 是否允许玩家互相伤害 |
| 无人暂停 | 服务器空人时是否暂停世界推进 |
| 网络刷新率 | 15–60，默认 15；越高越流畅但对带宽和 CPU 要求越高 |
| 洞穴开关 | **开启洞穴**后创建世界会出现洞穴分片（会额外占用约 1–2 GiB 内存，低配机器有提醒） |
| Steam 组限制 | 可限制仅指定 Steam 组成员入服（进阶） |

填完点击 **保存并重启**（实例运行中改动需重启生效；未启动过的实例保存后下次启动生效）。

> 令牌保存后不会明文回显，只显示掩码，属于正常现象。

## 12. 创建世界

世界在**首次启动实例时自动生成**，你要做的是提前把规则配好。进入 **世界管理**，点击实例进入 **世界设置**，页面分为"地上 / 洞穴 / 模组"三个页签（洞穴页签需先在房间设置开启洞穴）。

### 12.1 地上世界（Master）

- **世界规则**：按分组调整玩法细节——全局、活动、冒险家、世界、资源再生、非自然传送门资源、生物、敌对生物、巨兽、月亮变异等，每项可一键恢复默认档位；
- **世界生成**：预设默认为**联机生存**（SURVIVAL_TOGETHER）；地图生成后，部分世界生成选项将无法再改，想改尺寸/群落要趁生成前；
- **网络**：游戏端口 10999、Steam 认证端口 8766、Steam 主服端口 12346（默认即可，见 12.3）。

### 12.2 洞穴世界（Caves）

- 世界生成预设可选**标准洞穴**、**资源丰富**、**完全黑暗**等；
- 规则分组与地上类似，但面向洞穴生态；
- 洞穴地图在洞穴服务器首次启动时自动生成。

### 12.3 分片端口说明

每个分片有三个 UDP 端口，默认值：

| 分片 | 游戏端口 | Steam 认证端口 | Steam 主服端口 |
| --- | --- | --- | --- |
| 地上（Master） | 10999 | 8766 | 12346 |
| 洞穴（Caves） | 11000 | 8768 | 12348 |

一般无需修改。若改成其他端口，注意：端口不能与另一分片重复；安全组要放行新端口。

## 13. 主世界端口、洞穴端口需要手动开放吗？

**需要。** 面板只负责配置和启动游戏进程，不会替你操作云厂商的安全组；安装器也默认不修改本机防火墙。因此：

- 主世界的 10999/8766/12346（UDP）**必须手动放行**，否则玩家连不上；
- 开启洞穴后，11000/8768/12348（UDP）**同样必须手动放行**，否则会出现进洞穴崩线、世界加载卡住等问题；
- 放行方法见第 4 章。

常见误区：只放行了面板的 9527/tcp 就以为开好了——面板能打开不代表游戏能连。玩家反馈"搜不到房间/进不去"时，第一件事就是核对安全组 UDP 规则。

## 14. 安装与管理 Mod

1. 进入 **模组管理**，选择目标实例；
2. 在创意工坊列表中搜索 Mod（可按订阅数等排序），或直接输入创意工坊 ID；
3. 点击 **订阅**，面板自动通过 SteamCMD 下载 Mod 文件，列表中状态变为"已订阅"；
4. 点击 Mod 进入 **Mod 详情**，可调整该 Mod 的配置参数；
5. 回到 **世界设置** 的"模组"页签，把 Mod **启用**到地上/洞穴世界（洞穴 Mod 与地上 Mod 是分开启用的）；
6. 保存并重启实例生效。

订阅成功的 Mod 会引导你到世界设置开启；只订阅不启用是不会生效的。

## 15. 启动服务器

回到 **实例管理**，点击实例的 **启动**：

- **首次启动**会弹出"准备启动服务器"引导：
  - 若联网方式为公网但未配置 Klei 令牌，会直接引导你"去配置房间"——没有令牌不允许公网启动；
  - 可选择 **按当前配置启动**（已保存房间/世界设置时）或 **用默认配置启动**（直接使用离线房间和默认地图）；
  - 确认后面板按配置生成第一张地图（洞穴在洞穴服务器首次启动时同样生成）；
- **日常启动**：直接点启动即可；
- 启动后状态变为"运行中"，在实例详情能看到地上/洞穴两个分片的运行状态、资源占用，以及"连接信息"。

玩家进服方式：打开《饥荒联机版》→ **浏览游戏**，按房间名搜索即可。

> 地图生成后，多数世界生成选项不可再改。想换地图风格需要重置世界（控制台的 c_reset()，见 16.2）并重新生成。

## 16. 实例控制台

入口：**实例管理 → 实例详情 → 控制台**（或列表操作菜单中的"控制台"）。控制台是日常管理最常用的页面。

### 16.1 界面与页签

- **日志页签**：地上与洞穴（若开启）的游戏运行日志合并展示，每行带分片标签，支持自动滚动开关，实时推送；
- **面板消息页签**：你发送的命令回显与运行状态提示；
- **维护公告页签**：向游戏内全体玩家推送公告（编辑内容后一键推送），并保留推送历史。

### 16.2 发送命令

- 顶部命令输入框输入 DST 控制台命令（如 c_save()），点击发送；
- 可用单选切换命令送达的分片：**地上 / 洞穴**（洞穴未启用或未运行时不可选并有提示）；
- 实例**详情页**还有"命令中心"，提供常用操作的按钮化封装：

| 快捷命令 | 作用 | 风险 |
| --- | --- | --- |
| 保存 c_save() | 立即保存当前世界 | 无 |
| 回档 1/2/3 天 c_rollback(n) | 世界回退到 n 个游戏日前的存档点 | 有危险确认 |
| 重置世界 c_reset() | 丢弃当前世界并重新生成全新地图 | 有危险确认，不可恢复 |

自定义命令可发送任意 DST 控制台指令（踢人 c_kick()、公告 c_announce() 等），执行结果在面板消息页签查看。

### 16.3 什么时候用控制台

- 启动后看日志确认分片启动与互联成功；
- 玩家反馈异常时实时观察报错；
- 定期手动 c_save()（日常建议交给计划任务自动备份）；
- 世界出问题（地形改版、存档损坏）时回档或重置。

## 17. 备份与恢复

进入 **备份与恢复** 页面。这里管理所有实例的存档备份与面板数据库快照，日常备份**不再需要 SSH**。

### 17.1 创建备份（手动）

1. 页面顶部选择目标实例；
2. 点击 **创建备份**，可填写备注（如"开服首日存档"）；
3. 面板把该实例的 klei-storage（世界数据、房间配置、集群令牌）打包为 tar.gz；**实例运行中会先自动执行 c_save() 保存世界再打包**，不用担心丢进度。

### 17.2 恢复备份

1. 在列表中找到目标备份点，点击 **恢复**；
2. 确认弹窗会提示：**恢复要求实例已停止**（运行中会被拒绝），且恢复前会**自动创建一份"恢复前"安全备份**，恢复错了还能再翻回去；
3. 恢复完成后启动实例，验证世界状态即可。

### 17.3 下载与删除

- **下载**：点击备份的下载按钮，把 tar.gz 保存到本地电脑，实现异地容灾（重要服建议定期下载）；
- **删除**：删除单个备份文件，不可恢复。

### 17.4 导入外部存档

点击 **导入外部存档**，上传本地 Klei 存档压缩包（.zip / .tar.gz / .tgz）：

- 支持压缩整个 Cluster_x 目录，或整个 DoNotStarveTogether 目录，面板下载的备份包也可直接回导；
- 导入要求实例已停止且已完成游戏安装；
- 导入前自动创建"导入前"安全备份；上传后面板会先探测识别存档结构并提示警告。

适用场景：把本地/旧服务器的世界搬到这台服务器，或把下载的备份恢复到新实例。

### 17.5 数据库快照

点击 **创建数据库快照**，对面板 SQLite 数据库做一致性快照（VACUUM INTO），包含实例、账号与面板设置。快照用于面板自身数据的兜底恢复；升级前的数据库备份由安装脚本自动完成。

### 17.6 保留策略与自动备份

- 每个实例默认保留最近 **10 份**存档备份，超出自动淘汰最旧的；
- 系统级自动备份钩子默认开启：**更新服务端前**、**删除实例前**自动创建备份，备份类型分别标记为"更新前""删除前"；
- 备份文件在服务器上位于 /var/lib/game-server-hub/backups/（Docker 卷 gsh-backups）；
- 面板内备份不等于异地容灾，重要服务器请配合定时下载到本地。

## 18. 计划任务

进入 **计划任务** 页面，把重复性运维交给定时器。支持四种任务：

| 任务类型 | 作用 |
| --- | --- |
| 定时备份（实例存档） | 到点对所选实例执行一次存档备份（同 17.1，运行中也会先自动保存世界） |
| 定时重启 | 到点重启实例；适合每日凌晨清内存、应用更新 |
| 更新检查（SteamCMD） | 到点向 Steam 核对游戏版本，有新版本时提醒你更新 |
| 数据库快照（面板全局） | 到点对面板 SQLite 做一致性快照 |

**调度方式**（二选一）：

- **每日固定时刻**：如 04:30，时区可选 **北京时间**（默认）或 **服务器所在时区**；
- **每 N 小时**：间隔 1–168 的整数小时。

**创建步骤**：

1. 点击 **新建任务**；
2. 选择目标实例（数据库快照任务目标固定为"面板数据库"）、任务类型；
3. 选择调度方式并设置时刻/间隔；
4. 保存后任务进入列表，可随时 **编辑**、**删除**，列表中还能看到每个任务最近一次的执行结果（成功/失败/跳过）。

推荐配置：每日凌晨定时重启 + 每 6 小时定时备份 + 每日数据库快照。

## 19. 常见问题

### 玩家搜不到房间 / 连不上

按顺序排查：

1. 实例状态是否"运行中"，地上/洞穴分片是否都起来了（看控制台日志）；
2. 房间设置是否为公网联机且已保存 pds- 令牌；
3. **安全组是否放行了全部 UDP 端口**（主世界 3 个 + 洞穴 3 个，见第 4、13 章）——这是最常见原因；
4. 是否设置了房间密码而玩家没输入；
5. 服务器负载是否过高导致广播超时（看监控台）；
6. 直连地址是否真的可用：命令下方提示里，来自"出站 IP 探测"的地址在本机 / 家用 NAT / 容器环境下往往不可直连，开着系统代理时还可能指向代理出口（见 5.2、5.3）。

### 面板打不开

curl -fsS http://127.0.0.1:9527/health 在服务器本机执行：本机通而外网不通 → 安全组没放行 9527/tcp；本机也不通 → 按关键词查 [INSTALL.md 的 FAQ](INSTALL.md#faq按错误关键词排查)。

### 镜像拉取失败（Docker 模式）

GHCR 不可达时优先使用 Release 离线镜像包，或在 panel.env 配置 GSH_IMAGE_MIRRORS。详见 [INSTALL.md](INSTALL.md) 第 3.3、8 章。

### SteamCMD 下载游戏慢

启用 --network cn 安装，或按 INSTALL.md 配置下载区域/代理。

### 开洞穴后内存吃紧

洞穴分片额外占用 1–2 GiB。4 GiB 机器建议先关洞穴或少开 Mod；档位建议见 [MEMORY.md](MEMORY.md)。

### 忘记密码

见 6.5 节。
