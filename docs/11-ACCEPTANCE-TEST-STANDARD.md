# 验收测试标准

## 1. 验收目标

- 验证 v1 核心功能闭环可用、稳定、可运维。
- 统一模块级验收条件与系统级验收流程。

## 2. 模块验收条件

## 2.1 已实现/部分实现模块

### 模块 00 平台安装与运行时

- 安装脚本可执行，基础依赖检查通过。
- Docker 连接正常，运行时元信息可读。

### 模块 01 监控台

- 系统信息可查询并周期刷新。
- 网络实时图表可渲染，异常时有提示。

### 模块 02 节点与实例

- 本地节点可注册与展示资源状态。
- 实例可创建、安装、启停、更新、删除。
- 安装日志可查看并反映真实阶段。

### 模块 09 实例控制台

- 日志轮询可读，SSE 流可连接。
- 命令发送成功时可在日志中观测反馈。

### 模块 13 新手引导

- 首次进入关键页面有明确操作引导。
- 引导文案与实际能力一致，不含无效入口。

### 模块 14 游戏适配器

- DST 适配器链路可支持实例创建与启动。
- 适配器异常可输出可读错误信息。

## 3. 整体系统验收标准

- **功能完整性**：认证、实例生命周期、监控、控制台四大主链路可完成。
- **稳定性**：关键流程连续执行无阻断性错误。
- **可观测性**：日志、错误码、状态字段可支持排障。
- **一致性**：代码能力与文档状态一致。

## 4. 验收流程与方法

1. 准备环境：安装依赖、启动前后端、确保 Docker 可用。
2. 执行模块用例：按模块清单逐项验证。
3. 执行端到端场景：
   - 登录 -> 进入实例管理 -> 创建并安装实例 -> 启动 -> 控制台交互 -> 停止 -> 删除。
4. 记录结果：通过/失败、日志、复现步骤、修复建议。
5. 回归验证：修复后重复关键路径直至通过。

## 5. 验收产出物

- 验收记录表（日期、版本、执行人）。
- 问题清单（严重级别、定位、修复状态）。
- 发布建议结论（可发布/有条件发布/不可发布）。
