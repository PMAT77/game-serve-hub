## 场景 A：一键安装面板

**目标**：安装 ≤ 10 分钟。

**前置**：Ubuntu 22.04+ / Debian 12+，root 或 sudo，出站网络正常，磁盘 ≥ 4GB 可用。

**步骤**：

1. 执行官方安装命令（见 README / `scripts/install.linux.sh`）。
2. 等待脚本完成，记录输出的 Panel URL、管理员账号密码。
3. 浏览器访问 Panel URL，应出现登录页。

**期望**：

- [x] 脚本退出码 0，`install.status` 末行为成功（2026-05-18 已测）。
- [x] `docker compose ps` 显示 `panel` 为 running（SteamCMD 为按需任务，非必须常驻服务）。
- [x] 登录页可加载，无白屏（2026-05-18 已测）。

**失败排查**：`PANEL_LOG_DIR/install.status`、面板容器日志、`docker logs game-server-hub-panel`。

## 场景 B：首次登录与改密

**前置**：场景 A 完成；`FORCE_PASSWORD_CHANGE=1`。

**步骤**：

1. 使用初始密码登录。
2. 应跳转强制改密页，修改为满足规则的密码。
3. 进入主页，打开监控台。

**期望**：

- [ ] 未改密前调用实例 API 被拒绝或重定向。
- [ ] 改密后可访问 `/console/monitor`。
- [ ] 监控台显示 CPU/内存/磁盘、Docker 信息。

---

## 场景 C：创建 DST 实例并进服（核心）

**目标**：开服 ≤ 15 分钟（自创建实例起算）。

**前置**：场景 B；SteamCMD 可用（栈内或过渡期宿主机）。

**步骤**：

1. 进入 **节点 → 实例管理**，创建实例：游戏选饥荒，填写名称、安装路径、游戏端口。
2. 等待安装完成，状态为 `stopped`，安装进度 100%。
3. 进入 **房间管理**（或实例内 Cluster 配置）：设置房间名、密码（可选）、最大玩家数。
4. 进入 **世界管理**：确认 Master 已配置；可选启用洞穴。
5. 点击 **启动**，等待状态 `running`。
6. 打开 **实例控制台**，确认日志无致命错误；执行 `c_save()` 或快捷保存（若已实现）。
7. 使用 DST 客户端连接 `IP:game_port`（或集群密码 LAN/在线模式按配置）。

**期望**：

- [ ] 安装日志无连续失败；`last_error` 为空。
- [ ] Master 容器运行（`container_id` 有值，`docker ps` 可见 `game-<instanceId>-master`）。
- [ ] 客户端可进入游戏。
- [ ] 保存命令有响应日志（依赖控制台能力，见 FDS-09）。

**失败排查**：安装日志 API、`docker logs`、`<installPath>/klei-storage/.../Master/server.ini` 端口。

## 场景 D：启用洞穴（Shard）

**前置**：场景 C 中实例已安装未运行或已停止。

**步骤**：

1. 在世界管理中 **启用洞穴**。
2. 按提示重启（先 Master 后 Caves）。
3. 控制台分别确认 Master/Caves 日志（或统一入口标注 shard）。
4. 进游戏验证可进入洞穴层。

**期望**：

- [ ] 存在 `Caves/server.ini` 与 Caves 容器。
- [ ] 两 shard 同时 running 时客户端可下洞穴。

---

## 场景 E：Mod 安装（M2）

**前置**：场景 C 实例已安装。

**步骤**：

1. 打开 Mod 管理，搜索已知 Mod（如官方样例 ID）。
2. 一键安装并启用，调整加载顺序，保存。
3. 重启实例，进游戏确认 Mod 生效。

**期望**：

- [ ] `instance_mods` 有记录；磁盘有对应 workshop 内容。
- [ ] 冲突/依赖有基础提示（若适用）。

---

## 场景 F：备份与恢复（M2）

**步骤**：

1. 运行中或停止状态下创建 **手动备份**，填写备注。
2. 确认列表显示大小与时间；Community 下创建第 4 份时最早被删（若采用软限 3）。
3. 故意修改房间名或删除测试存档文件（测试环境）。
4. 从备份 **恢复**，二次确认。
5. 启动实例，验证配置/存档回到备份时点。

**期望**：

- [ ] 恢复后 Cluster 配置与备份一致。
- [ ] 恢复过程有明确停服提示。

**步骤**：

- [ ] 容器已删除（M0）；卷按策略保留或删除（与 FDS-02 一致）。
- [ ] 无僵尸 `running` 状态。
