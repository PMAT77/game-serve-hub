# FDS-12：通知与审计

- 里程碑：M3
- 优先级：P1
- 状态：规划态

## 1. 背景与目标

提供系统通知与操作审计能力，支撑可运维、可回溯、可治理的平台演进。

## 2. 角色与前置条件

- 角色：管理员、审计管理员
- 前置：关键模块输出结构化事件

## 3. 功能范围

- 通知中心（系统事件、任务结果、异常告警）
- 审计日志（谁在何时对什么对象做了什么）

## 4. 功能清单

- 站内通知列表（Community）
- 关键操作审计日志（Community）
- 外部通知通道（Pro 规划）

## 5. 接口与输入输出（规划）

- `GET /app/notifications`
- `POST /app/notifications/read`
- `GET /app/audit-logs`

审计字段建议：

- operator
- action
- targetType
- targetId
- result
- timestamp

## 6. 业务规则

- 高风险操作必须落审计日志。
- 通知与审计分离存储，避免耦合。
- 审计日志默认不可篡改。

## 7. 异常与边界

- 事件入库失败 -> 回退到本地日志并告警
- 通知堆积 -> 提供过期与归档策略

## 8. 非功能要求

- 查询性能可满足按时间和对象检索
- 保留策略可配置（如 30/90/180 天）

## 9. 验收标准

- 关键操作产生审计记录
- 通知可按状态检索与标记已读
- 故障事件可通过通知链路被发现

## 10. 后续里程碑

- Webhook/邮件/IM 通知
- 审计导出与合规报表
